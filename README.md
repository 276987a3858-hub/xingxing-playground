> 这里整理的是星星游乐场中适合对外公开的一小部分内容，主要写给愿意读代码的开发者。
> 它不是一份开箱即用的产品文档：**当前仓库不保证可以直接克隆后运行**，也不包含任何私人角色资料、真实对话或真实用户数据。
>
> 想先看实现，直接跳 [技术文档](docs/README.md)：整体架构、模块依赖、请求流程、记忆机制、存储结构、API 契约、部署说明。

## 项目是什么

星星游乐场是一个个人 AI 陪伴方向的实验。它把一套原本较完整的本地应用做减法后，聚合成一条可以读的技术链路：浏览器前端承载交互与本地数据，一个轻量的代理层负责静态资源分发和模型 API 转发，浏览器与外部硬件通信服务之间另有触摸交互的入口。

本次公开的范围是**完整的前端与服务端源码**，但明确剔除了：角色人设正文与个人画像、真实聊天记录与记忆数据、备份与日志、音频与表情包素材、以及一切密钥。源码里的人设引用已改为占位示例。

## 为什么开发

最初的想法很简单，想看看三件事能不能在低成本、少运维的前提下同时成立：

1. 把状态尽量留在用户自己的浏览器里（本地优先），而不是集中存到服务器。
2. 用一个单文件 Worker 兼顾页面托管与模型调用代理，避免维护独立后端。
3. 让网页能和一块实体开发板互动，把"屏幕里的陪伴"延伸到可触摸的硬件。

这不是产品化尝试，更接近一套边做边改的个人工程实践，因此很多地方带有实验性质。

## 技术栈与总体架构

- **前端**：原生 HTML / CSS / JavaScript，无前端框架；按功能拆成多个模块，通过浏览器全局对象挂载与协作。样式包含基础样式、语音气泡样式和一组设计变量（tokens）。
- **本地存储**：IndexedDB 保存结构化记录，`localStorage` / `sessionStorage` 保存少量会话与配置项。用户自填的 API Key 保存在浏览器本地（IndexedDB），发起 AI 请求时会随请求发送到代理；代理端如何处理该 Key，以实际实现为准。
- **PWA Web App Manifest**：入口页通过 `<link rel="manifest">` 引用了 `manifest.json`，但该文件在原项目目录中**并不存在**，属于悬空引用（页面不会因此报错，只是不会被当作可安装的 PWA）。它与下文的"图片素材清单"是两个不同的东西。
- **后端**：两个部署入口，代理行为大体对齐（不承诺完全等价）——
  - `src/worker.js`：单个 Worker 同时处理 `/api` 代理和静态资源分发（`env.ASSETS.fetch`）。
  - `functions/api.js`：Cloudflare Pages Function 版本，只处理 `/api`，静态资源交给 Pages 托管。文件注释说明其行为与 Worker 版对齐。
- **模型接口**：代理把请求转发到 OpenAI 兼容的 `chat/completions` 接口，服务端侧用环境变量 `DEEPSEEK_API_KEY` 以 Bearer 方式鉴权，响应以流式（`text/event-stream`）透传。前端另有一条"用户自填 API Key"的路径（见"隐私与安全边界"），两者是不同的调用模式，可同时存在。
- **部署**：原项目提供 Worker 和 Pages Function 两种部署入口，具体部署命令与配置依部署目标而定。公开仓库不包含完整的开箱即用部署环境。

一句话概括职责划分：**前端负责交互、状态和本地数据；代理层负责转发与托管，本身不持有浏览器里的业务状态。但要强调：代理不会去读取浏览器的 IndexedDB 或 `localStorage`，然而模型请求本身会携带聊天内容或上下文，代理会接触到请求文本并把它转发给上游模型服务**——因此不能说"代理看不到本地数据"。

## 已实现的技术方向

以下均可在本仓库代码中看到，属于**已实现**：

- 单文件 Worker 同时完成静态托管与 API 代理；Pages Function 作为另一个部署入口，代理行为大体对齐。
- 流式响应透传，Pages 版设置了 40 秒上游超时，并把超时与一般错误区分成不同错误码返回。
- 浏览器端用 IndexedDB 建立多个对象仓库并进行事务式读写。原项目中另有配套的本地数据查看、清理与迁移能力；这些属于原项目已有的能力，公开仓库不包含一套完整可运行的工具链。
- 前端模块化：AI 客户端、语音、用量统计、意图识别等活动模块通过全局对象组织。
- 请求管线抽出三个可独立复用的纯函数模块（时间、历史窗口、请求布局），并配有直接单元测试；它们不依赖项目其余部分。
- 提供一个"设备通信地址"配置项，供前端连接到外部硬件通信服务。这只是连接入口的**配置能力**，不等于完整的 ESP32 通信链路已经跑通。
- 一个 Node 脚本用于为**图片素材目录生成素材清单**（manifest.json）；它是构建期的素材整理脚本，不是入口页加载的运行时模块，也不是 PWA 的 Web App Manifest。

## 隐私与安全边界

- 仓库**不含**真实聊天记录、用户画像、关系资料、角色人格正文、机自述正文或任何真实用户数据。
- 仓库**不含**真实 API Key、Token、私人地址或账号标识；代码中出现的均为环境变量名或占位配置。
- **主要业务数据保存在浏览器本地**。但模型调用时，必要的聊天内容或上下文会作为请求体发送到代理，再由代理转发给上游模型服务；因此这里不承诺"所有数据始终只在本地"。
- **API Key 有两个来源，属于不同调用模式**：
  - 服务端环境变量 `DEEPSEEK_API_KEY`：配置在部署环境，由代理在转发时附加，前端不接触它的值。
  - 客户端自填 API Key：用户自填的 API Key 保存在浏览器本地（IndexedDB），发起 AI 请求时会随请求发送到代理；代理端如何处理该 Key，以实际实现为准。前端**确实持有**这把由用户自己填写的 Key。
  - 两者可同时存在；代理是否会以客户端传入的 Key 覆盖服务端配置，属于本次未核实的范围（待确认）。
- 代理默认通配 CORS 且缺少鉴权，仅适合个人本地/受控环境；**CORS 不是鉴权机制，不能替代鉴权**，也不应把这样的代理直接暴露到公网供他人使用。
- 鉴权、限流、配额管理是这类代理的通用改进方向；本说明不公开任何真实代理地址或可直接访问的入口。
- 与私人内容相关的模块未纳入本仓库，也不建议通过配置重新接回后公开部署。

## 不能克隆即用的说明（重要）

源码是完整的，但**仍然不能克隆后直接跑起来**，原因如下：

- **没有密钥**：`src/worker.js` / `functions/api.js` 从环境变量读取 `DEEPSEEK_API_KEY`；请复制 `.env.example` 为 `.dev.vars`（wrangler）或按你的平台注入 secret。仓库内不含任何真实密钥。
- **没有素材**：角色人设文本（`public/persona/*.txt`）、音频、表情包图片均不在仓库中，它们是私人内容或来源待确认的第三方素材。缺这些只会让对应功能失效，不影响代码阅读。
- **PWA Web App Manifest 缺失**：入口页引用的 `manifest.json` 在原项目中就不存在（悬空引用），并非本仓库的删减。
- **语音与硬件需要自有服务**：`public/shared/voice-config.js` 的 TTS 地址已替换为占位域名，硬件交互需要你自己的设备与端点。
- **人设是占位文本**：`public/shared/persona.js` 里的第一、二层已改为示例文本，原项目的私人人设不随仓库公开。
- 公开版本身不是一条经过完整回归测试的部署流水线。

仓库里**能直接跑**的是 `tests/shared/` 下的测试（见上文 `node --test`，630 项通过）。想跑起完整页面，按 [部署说明](docs/07-deployment.md) 第 6 节的顺序补齐密钥与素材即可。

如果你只是想了解思路，读代码与后面的《技术讨论》即可；如果你尝试运行，请预期需要自行补齐上述空缺。
