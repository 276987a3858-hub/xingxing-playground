# 技术文档索引

这组文档写给愿意读代码的开发者，目标是把「这个项目怎么组织、一次对话怎么走完、数据存在哪里」讲清楚，而不是提供一套可直接运行的产品。

## 阅读顺序

| # | 文档 | 回答的问题 |
|---|---|---|
| 01 | [整体架构](01-architecture.md) | 系统由哪几层组成，各层边界在哪 |
| 02 | [核心模块与依赖关系](02-modules.md) | 有哪些模块，谁调用谁，哪些已公开 |
| 03 | [消息与 AI 请求流程](03-request-flow.md) | 一条消息从输入到落库、再到请求上游，中间做了什么 |
| 04 | [历史记录与记忆机制](04-memory-and-history.md) | 历史窗口、按需检索、长期记忆、机自述各自负责什么 |
| 05 | [数据存储结构](05-data-storage.md) | IndexedDB / localStorage 里存了什么，记录长什么样 |
| 06 | [API 接口关系](06-api.md) | 前端与代理之间的契约、错误语义、已知偏差 |
| 07 | [部署与运行说明](07-deployment.md) | 两种部署入口怎么跑，缺少哪些依赖 |

如果是第一次读，建议按 01 → 03 → 02 的顺序：先看全局，再看主链路，最后回来看模块清单。

## 标记约定

文档中的判断分两种，混用会误导，所以显式标注：

- **✅ 已核实**：在代码中读到实现，并附文件与行号。
- **⚠️ 待核实**：只读范围内无法确认，或代码与注释/文档不一致；不写成结论。

所有行号基于 2026-11-26 的原项目工作区（`public/app.js` 共 5,075 行）。若你手上的版本行号有偏移，以函数名为准检索。

## 范围声明

- 文档只描述结构与机制，**不包含**角色人设正文、提示词原文、真实聊天内容、记忆正文、密钥或任何用户数据。
- 涉及未公开模块时，用「角色人设层」「私有适配层」等中性称呼，只说明它在链路中的位置与接口形状。
- 本仓库的代码是原项目的**子集**，因此文档描述的完整链路中，有一部分文件不在仓库里；这种情况会在对应小节注明。

## 与 README 的关系

根目录的 [README](../README.md) 讲项目是什么、为什么这样设计、有哪些边界；本目录讲具体实现。两者若有冲突，以代码为准，并欢迎提 issue 指出。
