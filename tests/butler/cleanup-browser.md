## 2. 测试环境

- **浏览器**：Edge（`--headless=new`），独立 `--user-data-dir`（`%TEMP%\bl-cleanup-prof`），**与用户真实浏览器 profile 完全隔离**

- **测试数据库**：`star_cleanup_test`（`messages` only，`id` 自增），每次用「删库重建」保证干净
- **真实数据库**：`star_fifi_room` 仅做 **`getAll()` 只读清点**，比对前后消息总数，绝不写入
- **服务**：`npm run dev` → `http://127.0.0.1:8787`
- **运行方式**：`node tests/butler/cleanup-browser.mjs [--real]`（`--real` 追加真实库只读加载检查）

## 3. 测试方法

1. **注入原生 IDB 助手**：在页面里挂 `window.__raw`，提供 `open`（不带版本号）/ `tx` / `all` / `reset`（删库重建，测试库专用）/ `clear`。
2. **播种**：写入 4 条记录 —— 今天 user、今天 assistant、昨天 user、**无 `time` 字段** assistant，返回自增 ID。
3. **重载页面**：`Page.navigate` 到 `?db=star_cleanup_test`，重新注入助手（重载会清掉全局），用 `waitFor` 轮询 `window.__CK.state` 直到就绪。
4. **UI 驱动**：直接 `element.click()` 走真实事件路径；断言读 DOM（勾选数、按钮 `disabled`、状态条文案、弹层条目数）。
5. **破坏性场景**：在**另一个连接**上把某条消息的 `time` 改成昨天 / 直接 `delete` 掉某条，再点确认，验证整批取消。
6. **收尾**：清空测试库，比对真实库消息总数前后一致，统计 `Runtime.exceptionThrown` + `console.error` 数量为 0。

## 5. 测试中发现并修掉的真实缺陷（经验）

1. **状态条被刷新冲掉**
   `load()` 开头调用了 `setStatus('', '')`，导致「删除失败/成功」提示刚显示就被随后的 `load()` 清空 ——
   表现为「点了确认没有任何反馈」。修法：从 `load()` 里移除清空逻辑，状态只由业务结果显式设置。
   → **教训：任何「操作后刷新列表」的流程，都不该在刷新函数里重置提示区。**

2. **删库会关掉页面连接**
   测试用 `indexedDB.deleteDatabase()` 重建测试库时，页面已有的连接因 `versionchange` 被自动 `close()`，
   后续 `transaction` 报 `The database connection is closing`。修法：删库后必须**重新导航页面**让连接重建。
   → **教训：验证脚本里做 destructive setup 后，要重载页面再断言。**

3. **`open(name)` 会创建空库**
   不带版本号打开不存在的库会创建一个 **0 个 store 的 v1 空库**。页面因此需要在 `onupgradeneeded` 里打标记，
   直接报「没有找到聊天数据库，请先打开房间页面」，而**不能顺手建 store**（否则会篡改产品库结构）。
   → 该行为已在隔离 profile 中实测确认：空库保持 0 store，页面优雅报错。

4. **`node --test tests/butler/` 目录形式会误报**
   本机 Node 把目录当模块入口，报 1 个 `ERR_TEST_FAILURE`，**不是测试失败**。
   正确写法：`node --test tests/butler/*.test.mjs`（当时全量 121/121）。

## 6. 复刻建议（若将来重建同类页面）

- 必备闸门顺序：**时间在范围内 → 记录仍存在 → 角色合法 → 再删**；任一不符 `tx.abort()`，用 `onabort` 回传原因。
- 成功判定不能只看 `oncomplete`，还要校验 `deleted.length === ids.length`（防「事务成功但少删」）。
- 一律「默认零选中 + 不自动判 OOC」：不做任何自动推荐，人只信自己勾的那几条。
- 测试必须用独立库 + 独立 profile，真实库只允许只读清点对比。
